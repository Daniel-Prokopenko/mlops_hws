    # Порівняння образів: Fat vs Slim

    ## Команди, якими знімались метрики
    1) Розмір:
       docker image ls | grep -E "ml-fat|ml-slim"

    2) Кількість шарів:
       docker history --no-trunc ml-fat
       docker history --no-trunc ml-slim

    3) Наявність зайвих інструментів:
       docker run --rm ml-fat bash -lc "which git || true; which vim || true; which gcc || true"
       docker run --rm ml-slim sh -lc "which git || true; which vim || true; which gcc || true"

    ## Результати (заповни своїми реальними числами)
    - Fat image size:  ____________  (очікувано: >1GB)
    - Slim image size: ____________

    - Fat layers count:  ____________
    - Slim layers count: ____________

    ## Що зайве в Fat (приклади)
    - build-essential, gcc, git, vim, wget — для runtime inference не потрібні
    - pip cache (якщо не чистити) може збільшувати шари
    - зайві apt-пакети та їх метадані

    ## Чому Slim менший
    - Multi-stage: залежності ставляться в builder, а в runtime копіюється лише venv + код + модель
    - --no-cache-dir у pip: не зберігає кеш
    - У runtime не викликається apt (нема apt-шарів)

    ## Подальша оптимізація (ідеї)
    1) Зменшити базовий образ:
       - спробувати python:3.11-alpine НЕ вийде для torch (нема сумісних коліс),
         але можна тестувати distroless + скопійований інтерпретатор (складніше).

    2) Виносити модель з образу:
       - зберігати model.pt в volume або скачувати при старті (якщо інтернет дозволено).
       - плюси: оновлення моделі без rebuild образу.

    3) Квантизація/оптимізація моделі:
       - dynamic quantization (для деяких архітектур)
       - torch.compile / torchscript оптимізації
       - перейти на ONNX + onnxruntime (часто легше та швидше для CPU)

    4) Увімкнути .dockerignore:
       - щоб випадково не копіювати зайве (datasets, venv, кеші)
